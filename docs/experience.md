# EDUCONNECT — 사용자 경험

## Foundation (기반)

- **제품:** 'EDUCONNECT · 모두의 AI 교육 에이전트'. 하나의 반응형 Next.js 웹 앱이다. 네이티브 앱은 없다(intent 2장, D-1).
- **보호자 관점:** 모바일 폭(360~767px) 우선. 로그인하면 챗봇 홈으로 들어간다. 하단 탭은 챗봇·일정·자녀 세 개다(D-13).
- **기관 관점(학원 담당자·학교 담당자):** 데스크톱 폭(1280px 이상) 기준. 로그인하면 자기 기관의 관리 화면으로 들어가고, 왼쪽 사이드바로 이동한다(D-13).
- **UI 시스템:** KDS(KT UX Design System 2.0). 색·글꼴·간격·컴포넌트 모양은 KDS를 따르고, 이 문서는 동작 규칙만 적는다. 보호자 챗봇은 KDS AI 화면 구조(`kds-topnav` → `kds-chat` → 추천 질문 → `kds-prompt-dock`), 기관 화면은 KDS PC 틀(`kds-gnb` + `kds-lnb` 왼쪽 메뉴)을 쓴다. 심플하고 세련되게, 라이트 모드만, 한국어 단일이다(D-5·D-13).
- **공통 머리:** 모든 화면 머리에 "EDUCONNECT · 모두의 AI 교육 에이전트"를 보인다. 보호자 챗봇 머리에는 모두의 AI 연동 상태 "모의"와 AI 공급자 표기 "Azure OpenAI(국내 리전)"를 함께 보인다(REQ-12). 엔드포인트 호스트명 같은 설정값은 어떤 화면에도 나오지 않는다(REQ-10).
- **시드 데이터 표기:** 화면 아래(푸터)에 "예시 데이터"를 표시한다. 학교·학원·계정은 모두 목업이다.
- **입력 문서:** docs/intent.md(확정), docs/project-brief.md(final), docs/prd.md(final). 요구·조건 원문은 PRD를 따르고, 이 문서는 그 요구가 화면에서 어떻게 보이고 움직이는지만 정한다.

## Information Architecture (화면 구성)

| 화면 | 진입 경로 | 목적 | 사용 권한 |
| --- | --- | --- | --- |
| 로그인 | 앱 첫 진입, 로그아웃 뒤, 세션이 끝난 뒤 | 시드 계정 아이디·비밀번호로 로그인. 역할에 따라 보호자 챗봇 홈·학원 프로그램 관리·학교 시간표 관리로 보낸다 | 모두(로그인 전) |
| 보호자 챗봇 홈 | 보호자 로그인 직후, 하단 탭 '챗봇' | 대화로 조건 말하기, 조건 카드 확인·수정·저장, 추천 요청, 일정 생성 요청 | 보호자 |
| 조건 카드 | 챗봇 홈 대화 안(AI 답변 아래 카드), 카드의 '고치기'는 바텀시트 | 추출된 조건(대상 자녀·선호 과목·목표 월 예산·예산 상한·학원 유형·기준 위치·가능 요일·밀도)을 보고 고쳐 자녀별로 저장 | 보호자(자기 자녀만) |
| 추천 비교 | 챗봇 홈 대화 안 '추천 보기' 결과, 일정 초안의 '바꾸기' | 후보 프로그램을 학원명·과목·유형·요일·시간·월 교습비·월 기타경비·이동 근사·추천 이유로 비교 | 보호자 |
| 일정 초안 | 챗봇 홈의 '일정 만들기' 결과, 일정 탭의 초안 행 | 월~일 주간 일정(학교 시간 + 학원 수업), 월 학원비 합계와 내역, 규칙 검증 결과, 빼기·바꾸기·확정 | 보호자(자기 자녀만) |
| 일정 탭 | 하단 탭 '일정' | 자녀별 확정 계획과 일정 초안 목록, 영향 표시 | 보호자(자기 자녀만) |
| 확정 계획 상세 | 일정 탭의 계획 행 | 확정된 주간 일정과 월 학원비, 영향 사유·초과 금액, '조정안 보기' | 보호자(자기 계획만) |
| 조정안 | 확정 계획 상세의 '조정안 보기' | 규칙 위반 0건인 대안 일정을 기존 계획과 나란히 보고 수락·거절. 대안이 없으면 완화할 조건 | 보호자(자기 계획만) |
| 자녀 탭 | 하단 탭 '자녀' | 자녀 목록, 자녀 등록·수정(별칭·만 나이·학년·학교·관심사·교육 목표·기존 일정), 하교 시각 직접 입력 | 보호자(자기 자녀만) |
| 학원 프로그램 관리 | 학원 담당자 로그인 직후, 사이드바 '프로그램' | 자기 학원 프로그램 목록·등록·수정·삭제 | 학원 담당자(자기 학원만) |
| 학교 시간표 관리 | 학교 담당자 로그인 직후, 사이드바 '시간표' | 학년별 정규 시간표(요일·하교 시각)와 방과후 프로그램 등록·수정 | 학교 담당자(자기 학교만) |
| 영향 확인 | 기관 저장 직후 결과 줄의 '영향 보기', 사이드바 '영향 확인' | 이 기관 변경으로 영향받는 계획 수(개수만)와 변경 항목 | 학원 담당자·학교 담당자(자기 기관만) |

- 보호자는 기관 화면 경로를, 기관 담당자는 보호자 화면 경로를 열 수 없다. 남의 기관·자녀·계획은 화면에서 목록에 나오지 않고, 직접 주소로 열면 '찾을 수 없음'(서버 404)을 보인다.
- 조건 카드·추천 비교·일정 초안은 챗봇 대화 흐름 안에 이어 붙는 화면이다. 별도 하단 탭을 만들지 않는다.

## Voice and Tone (문구)

기본은 해요체, 정책·권한·인증 안내는 하십시오체(KDS 문구 규칙). PRD 확인 조건에 적힌 문구는 글자 그대로 쓴다(시험이 그 문구를 찾는다).

| 쓰는 문구 | 쓰지 않는 문구 |
| --- | --- |
| "겹치는 수업이 있어요" · 칸 표시 "시간 중복" | "충돌 발생", "오류가 발생했습니다" |
| "월 학원비 1,020,000원" + 내역 "교습비 · 기타경비" | 합계에 '교습비등'·'총비용'·'수강료 합계' |
| "이동 15분(근사)" · "1.2km(근사)" | 근사 표시 없는 "이동 15분" |
| "조건을 만족하는 일정이 없습니다" + 완화할 조건 | "검색 결과 없음", "일정 생성 실패" |
| "영향 있음 · 시간 중복", "영향 있음 · 예산 초과 50,000원" | "충돌 알림", "경고!" |
| "영향받는 계획 1건" | 자녀 별칭·보호자 이름을 넣은 기관용 문구 |
| "아이디 또는 비밀번호가 올바르지 않습니다" | "없는 아이디예요"(계정 존재를 드러냄) |
| "로그인 시도가 많아 15분 동안 잠겼습니다" | "계정이 차단되었습니다" |
| "법정대리인 동의 확인이 필요합니다" | "부모 동의 필요" |
| "학교 시간표가 없습니다. 하교 시각을 직접 입력해 주세요" | "데이터 없음" |
| "AI 설명을 불러오지 못해 기본 설명을 보여 드려요" | 모델 오류 원문, 상태 코드, 설정 이름 |
| "보호자", "학원 담당자", "학교 담당자" | "학부모", "부모", "관리자" |
| "미공개" | 0원, 빈칸 |

- 금액은 `1,000,000원`, 월 금액은 `월 1,000,000원`, 시간은 24시간 `14:30`으로 쓴다.
- 챗봇 답변은 결과를 먼저, 이유를 뒤에 쓴다. 예: "영어 2곳·수학 2곳으로 월 1,020,000원 일정을 만들었어요. 학교 하교 뒤 이동 시간을 넣었어요."
- 버튼은 결과 동사로 쓴다: "조건 저장", "추천 보기", "일정 만들기", "빼기", "바꾸기", "일정 확정", "조정안 수락", "그대로 두기", "프로그램 저장", "시간표 저장", "삭제".

## Component Patterns (구성 요소 동작)

| 구성 요소 | 쓰는 곳 | 동작 규칙 |
| --- | --- | --- |
| `kds-topnav` | 보호자 화면 머리 | 제품명·부제, '모의' 연동 태그(`kds-tag`), 공급자 표기, 로그아웃 버튼. 로그아웃을 누르면 세션을 끝내고 로그인 화면으로 간다 |
| `kds-bottomnav` | 보호자 화면 하단 | 챗봇·일정·자녀 3개. 현재 탭은 `aria-current="page"`. 탭을 바꿔도 챗봇 입력 중 문장과 대화 내역은 유지한다 |
| `kds-chat`(`kds-chat__user`·`kds-chat__answer`·`kds-chat__thinking`) | 챗봇 홈 | 사용자 말만 말풍선, AI 답변은 본문. 처리 중에는 관찰 가능한 단계 문구("조건을 정리하는 중", "학교 시간표와 학원을 맞춰 보는 중")를 `role="status"`로 한 줄 보인다. 새 답변이 오면 맨 아래로 스크롤한다 |
| `kds-prompt-dock` | 챗봇 홈 하단 | 빈 값이면 보내기 비활성. 보내는 동안 입력값을 지우지 않고 보내기를 막는다. 응답이 오면 입력을 비운다 |
| 추천 질문(`kds-list` 행) | 챗봇 홈 첫 화면 | 3개: "초5 아이 영어·수학 위주로 월 100만원 전후로 촘촘하게", "저장한 조건으로 일정 만들어 줘", "확정한 일정에 바뀐 게 있어?". 누르면 바로 보낸다 |
| 조건 카드(`kds-card` + `kds-kv`) | 챗봇 답변 아래 | 추출된 8개 조건을 이름·값 쌍으로 보인다. 값이 없는 항목은 "정하지 않음". '조건 저장'을 누르면 자녀별로 저장하고 `kds-toast` "조건을 저장했어요"를 보인다. '고치기'를 누르면 바텀시트를 연다. 저장 전에는 '추천 보기'·'일정 만들기'가 마지막 저장값이 아니라 카드에 보이는 값으로 동작하지 않도록, 저장하지 않은 수정이 있으면 두 버튼을 막고 "먼저 조건을 저장해 주세요"를 보인다 |
| `kds-sheet`(조건 고치기) | 조건 카드 '고치기' | 필드: 대상 자녀(`kds-radio`), 선호 과목(`kds-chips` 다중), 목표 월 예산·예산 상한(숫자 입력, 원), 학원 유형(`kds-chips` 다중: 교과 학원·예체능 학원·교습소·방과후), 기준 위치(시드 위치 목록 `select`), 가능 요일(`kds-chips` 월~일), 밀도(`kds-radio`: 촘촘하게·보통). 예산 상한이 목표보다 작으면 필드 오류. '적용'을 누르면 시트를 닫고 카드 값이 바뀐다(아직 저장 전) |
| 추천 비교표(`kds-table`, 모바일은 `kds-card` 목록) | 챗봇 '추천 보기' 결과 | 행: 학원명·과목·유형·요일·시간·월 교습비·월 기타경비·이동 근사(거리·시간 + "근사")·추천 이유. 순서는 서버가 정한 순서 그대로(화면에서 다시 정렬하지 않음). 금액이 미공개·마감·대상 학년 불일치 프로그램은 서버가 빼서 오므로 화면에 나오지 않는다 |
| 주간 일정표(페이지 CSS 격자, 토큰 사용) | 일정 초안·확정 계획 상세·조정안 | 월~일 열, 시각 행. 학교 시간은 회색 고정 칸, 학원 수업은 과목·학원명·시각 칸, 칸 사이에 "이동 15분(근사)". 위반 칸에는 아이콘+글자 태그(`kds-tag--critical` "시간 중복"·"이동 부족"). 모바일 폭에서는 요일별 세로 목록으로 바뀐다 |
| 월 학원비 요약(`kds-kv` + `kds-cta-bar`) | 일정 초안 하단 고정 | "월 학원비 1,020,000원"과 예산 상한, 펼치면 프로그램별 교습비·기타경비 내역. 상한을 넘으면 `kds-tag--critical` "예산 초과 N원" |
| 빼기·바꾸기 버튼(`kds-button--xsmall`) | 일정 초안의 학원 수업 칸 | '빼기'는 바로 그 수업을 빼고 서버가 다시 검증한 결과(위반·합계)를 보인다. '바꾸기'는 같은 과목 후보 비교표를 시트로 열고, 고르면 그 후보로 바꾼 뒤 다시 검증한다 |
| '일정 확정' 버튼 | 일정 초안 하단 CTA | 위반이 1건 이상이면 비활성이고 바로 위에 "겹치는 수업이 있어요. 바꾸거나 빼 주세요"를 `kds-info-line`으로 보인다(위반이 예산 초과뿐이면 "예산을 넘었어요. 바꾸거나 빼 주세요"). 위반 0건이면 누를 수 있고, 확정하면 일정 탭으로 가서 확정 계획을 보인다 |
| 영향 태그(`kds-tag--warning`) | 일정 탭 계획 행, 확정 계획 상세 | "영향 있음 · 시간 중복" / "영향 있음 · 이동 부족" / "영향 있음 · 예산 초과 N원" / "영향 있음 · 내용 변경". 여러 사유면 한 태그에 가운뎃점으로 잇는다 |
| 조정안 비교 | 조정안 화면 | 기존 계획과 대안을 위아래로 보이고 바뀐 칸을 굵게 표시. '조정안 수락' → 확정 계획을 대안으로 바꾸고 영향 태그를 지운다. '그대로 두기' → 기존 계획을 유지하고 영향 태그를 남긴다. 두 행동 모두 `kds-toast`로 결과를 알린다 |
| 자녀 등록 폼(`kds-field`) | 자녀 탭 | 필드: 별칭, 만 나이, 학년(`select`), 학교(시드 학교 `select`), 관심사, 교육 목표, 기존 일정(요일·시작·끝·내용 반복 추가). 실명·연락처 칸은 없다. 만 나이가 14 미만이면 '법정대리인 동의 확인(모의)' `kds-checkbox`가 나타나고, 체크하기 전에는 저장 버튼이 비활성이며 "법정대리인 동의 확인이 필요합니다"를 보인다 |
| 하교 시각 직접 입력 | 일정 만들기 때 학교 시간표가 없는 학년 | `kds-notice` "학교 시간표가 없습니다. 하교 시각을 직접 입력해 주세요" + 요일별 하교 시각 입력. 입력하면 자녀의 하교 시각 직접 입력(`manual_dismissal`)으로 저장하고 일정 만들기를 이어 간다 |
| `kds-lnb` | 기관 화면 왼쪽 | 학원 담당자: 프로그램·영향 확인. 학교 담당자: 시간표·영향 확인. 현재 메뉴 `aria-current="page"` |
| 프로그램 목록(`kds-table`) | 학원 프로그램 관리 | 열: 과목·유형·요일·시간·월 교습비·월 기타경비·강사·대상 학년·정원/현재 인원·상태(공개·미공개·마감). 행의 '수정'은 같은 폼을 채워 연다. '삭제'는 `kds-popup` 확인("이 프로그램을 삭제할까요?", 버튼 "삭제"·"취소") |
| 프로그램 폼(`kds-field`) | 학원 프로그램 관리 | 과목, 유형(`select`), 요일(`kds-chips`), 시작·종료 시각, 월 교습비(비우면 미공개), 월 기타경비, 강사, 대상 학년(시작~끝), 정원, 현재 인원, 위도·경도. 저장 시 칸별 오류를 칸 옆에 보이고 첫 오류 칸으로 포커스를 옮긴다. 저장되면 목록으로 돌아가 `kds-toast` "프로그램을 저장했어요" |

| 저장 결과 줄(`kds-info-line`) | 기관 저장 직후 | 확정 계획에 쓰인 대상을 바꿨으면 "영향받는 계획 1건"과 '영향 보기' 링크를 보인다. 0건이면 "영향받는 계획이 없어요" |

## State Patterns (상태)

모든 화면에 공통으로 적용하는 상태 처리다. 흐름별 상태는 아래 Key Flows의 흐름 상세에 적는다.

| 상태 | 화면 | 처리 | 복구 방법 |
| --- | --- | --- | --- |
| 불러오는 중 | 모든 목록·일정·챗봇 | 영역 자리를 유지한 스켈레톤(`aria-busy="true"`), 버튼은 비활성 + "처리하고 있어요". 챗봇은 `kds-chat__thinking` 단계 문구 | - |
| 빈 상태 | 일정 탭·자녀 탭·프로그램 목록·영향 확인 | `kds-empty` 한 줄과 첫 행동: "아직 확정한 일정이 없어요" + '챗봇에서 일정 만들기', "등록한 자녀가 없어요" + '자녀 등록', "등록한 프로그램이 없어요" + '프로그램 등록', "영향받는 계획이 없어요" | 첫 행동 버튼 |
| 오류 | 모든 화면 | `kds-info-line--error` "응답을 받지 못했어요. 입력은 그대로 있어요." + '다시 시도'. 서버 오류 원문·상태 코드·설정값은 보이지 않는다. AI 호출 실패는 오류로 보이지 않고 대체 경로 결과를 보인다(아래 AI 상태) | '다시 시도' |
| 권한 없음 | 직접 주소로 남의 자원·다른 역할 화면 접근 | 남의 자원: `kds-empty` "찾을 수 없어요"(존재를 드러내지 않음). 역할에 맞지 않는 화면: "접근 권한을 확인하십시오" + 내 홈으로 가기. 세션이 끝났으면 "오래 쓰지 않아 자동으로 로그아웃했어요" + 로그인 화면 | 내 홈·로그인 |
| 저장 실패 | 조건 카드·자녀 폼·프로그램 폼·시간표 | 입력값을 지우지 않고 칸 옆 오류(`kds-field--error` + `aria-invalid`), 첫 오류 칸으로 포커스. 네트워크 실패면 폼 위에 "저장하지 못했어요. 입력은 그대로 있어요." | 다시 저장 |
| AI 대체 경로 | 챗봇 조건 추출·추천 이유 | 키가 없거나 Azure OpenAI가 오류·스키마 불일치 응답을 내면 규칙 추출·템플릿 설명으로 같은 화면을 보인다. 추천 이유 칸 아래 작은 회색 글씨 "AI 설명을 불러오지 못해 기본 설명을 보여 드려요". 흐름은 멈추지 않는다 | 필요 없음(자동) |
| 조건 불만족 | 일정 초안·조정안 | `kds-empty` "조건을 만족하는 일정이 없습니다"(조정안은 "조건을 만족하는 대안이 없습니다") + 완화할 조건 목록(예산 올리기·요일 늘리기·과목 줄이기 중 서버가 준 것) + '조건 고치기' | 조건 고치기 |
| 확정 실패 | 일정 초안 | 확정 요청이 위반(409)으로 거절되면 응답의 위반으로 초안을 다시 그린다(칸 태그, 확정 비활성). 예산 초과는 응답의 초과 금액으로 요약에 "예산 초과 N원"을 보인다. 신청할 수 없게 된 프로그램(422 `unknown_program`)이면 그 칸에 `kds-tag--critical` "신청 불가"와 `kds-info-line` "신청할 수 없게 된 수업이 있어요. 바꾸거나 빼 주세요"를 보이고, 초안을 바꿀 때까지 '일정 확정'을 비활성으로 둔다 | 빼기·바꾸기 |

## Interaction Primitives (조작)

- 보호자는 대화가 주 조작이다. 같은 일을 하는 버튼(조건 저장·추천 보기·일정 만들기)을 답변 아래에 함께 둔다. 대화로 말해도, 버튼을 눌러도 같은 서버 동작을 한다.
- 조건은 대화로 바뀌어도 조건 카드에서 사람이 확인·저장해야 확정된다. LLM이 추출한 값을 바로 저장하지 않는다.
- 일정 판정(중복·이동·예산·밀도)과 합계는 항상 서버 결과를 보인다. 화면에서 다시 계산하거나 LLM 문장에서 숫자를 읽어 쓰지 않는다.
- 기관 담당자는 폼 입력과 표 편집이 주 조작이다. 저장은 명시적인 '저장' 버튼으로만 한다(자동 저장 없음).
- 삭제·확정처럼 되돌리기 어려운 행동만 확인 팝업을 쓴다. 빼기·바꾸기는 초안 안에서 바로 반영한다.
- 금지 패턴: 매번 재로그인 요구, 자녀 연결용 별도 앱·다단계 승인(intent 6장 피할 패턴), 색만으로 상태 전달, `div` 클릭, 자동 재생 움직임, 화면에 모델 내부 추론 원문 표시.

## Accessibility Floor (접근성)

- 목표 WCAG 2.2 AA. 보호자 챗봇·일정·자녀, 학원 프로그램 관리, 학교 시간표 관리 화면은 axe(WCAG 2.2 AA 규칙) 위반 0건(AC-13.1).
- 키보드만으로 로그인 → 챗봇 조건 입력 → 조건 저장 → 일정 만들기 → 일정 확정까지 마칠 수 있고, 포커스 표시가 항상 보인다(AC-13.2). 조건 카드·비교표·일정표 안의 버튼은 문서 순서대로 Tab이 돈다.
- 시트·팝업: 열면 안으로 포커스, Tab은 안에서만, Escape로 닫힘, 닫으면 연 버튼으로 돌아간다.
- 챗봇 새 답변·저장 결과·영향 표시는 `aria-live="polite"` 한 곳에서 알린다. 위반·영향 태그는 아이콘과 글자를 함께 쓴다.
- 모든 입력에 보이는 라벨을 쓴다(placeholder를 라벨로 쓰지 않음). 터치 영역 44px 이상. 360px 폭에서 한국어 문구가 잘리지 않는다.
- 주간 일정표는 표 의미(요일 머리·시각)를 보조기기에 전달한다. 모바일 요일별 목록은 요일을 제목으로 둔다.
- `prefers-reduced-motion`이면 움직임을 멈추고 진행 문구는 남긴다.

### FLOW-01 보호자 챗봇 조건→추천·비교→일정 생성·수정→확정

**사용자·상황:** 초5·중1 두 자녀를 둔 맞벌이 보호자(데모 보호자 계정). 평일 저녁, 퇴근 버스에서 휴대폰으로 다음 달 초5 자녀의 학원 일정을 정한다(intent 7장 장면 1).

1. 챗봇 홈에서 추천 질문을 누르거나 "초5 아이 영어·수학 위주로 월 100만원 전후로 촘촘하게"를 입력해 보낸다. "조건을 정리하는 중"이 잠깐 보인다.
2. 답변 아래 조건 카드에 대상 자녀=초5 자녀, 선호 과목=영어·수학, 목표 월 예산=1,000,000원, 예산 상한=1,100,000원, 밀도=촘촘하게가 보인다. 비어 있는 기준 위치·가능 요일은 '고치기' 시트에서 채운다(기본값: 기준 위치=자녀 학교, 가능 요일=월~금). '조건 저장'을 누른다.
3. '추천 보기'를 누르면 비교표에 영어·수학 후보가 학원명·유형·요일·시간·월 교습비·월 기타경비·이동 근사·추천 이유와 함께 나온다.
4. '일정 만들기'를 누르면 월~일 일정표에 학교 시간과 학원 수업이 함께 나오고, 하단에 월 학원비 합계가 보인다.
5. 영어 수업 하나를 '바꾸기'로 다른 후보로 바꾸거나 '빼기'로 뺀다. 그때마다 위반 표시와 월 학원비가 다시 계산된다.
6. **가치 전달 순간:** 학교 시간과 겹치지 않고 수업 사이에 "이동 N분(근사)"가 확보된 영어·수학 주 2회 이상 일정과 "월 학원비 1,0XX,XXX원"이 한 화면에 보인다. '일정 확정'을 누르면 일정 탭에 확정 계획으로 저장된다.

### FLOW-02 기관 변경→영향 표시→조정

**사용자·상황:** 학원 A 담당자가 다음 달부터 수학 반 시간을 옮기고 교습비를 올린다. 그 수학 반을 쓰는 확정 계획을 가진 보호자는 저녁에 일정 탭을 연다(intent 7장 장면 2). 학교 담당자가 하교 시각을 바꿀 때도 같은 흐름이다(장면 3 끝난 뒤 상태).

1. 학원 A 담당자가 프로그램 관리에서 수학 프로그램의 요일·시간이나 월 교습비를 고쳐 '프로그램 저장'을 누른다.
2. 저장 결과 줄에 "영향받는 계획 1건"과 '영향 보기'가 보인다. 영향 확인 화면에는 계획 수와 바뀐 항목만 있고 자녀·보호자 정보는 없다.
3. 보호자가 일정 탭을 열면 그 계획 행에 "영향 있음 · 시간 중복"(또는 "영향 있음 · 예산 초과 50,000원")이 보인다.
4. 계획을 열어 '조정안 보기'를 누르면 기존 계획과 규칙 위반 0건인 대안이 위아래로 보인다.
5. **가치 전달 순간:** 보호자가 내 계획의 무엇이 왜 깨졌는지와 대안 일정을 한 화면에서 보고 '조정안 수락'을 누르면 확정 계획이 대안으로 바뀌고 영향 표시가 사라진다. '그대로 두기'를 누르면 기존 계획이 유지되고 영향 표시가 남는다.

### FLOW-03 학교 시간표 입력

1. 사이드바 '시간표'에서 5학년 탭을 연다. 요일별 하교 시각 행이 보인다.
2. 수요일 하교 시각을 13:40으로 고치고 '시간표 저장'을 누른다. 표에 13:40이 보이고 `kds-toast` "시간표를 저장했어요"가 나온다.

4. **가치 전달 순간:** 그 학교 초5 자녀의 일정을 만들면 수요일 학원 수업이 모두 13:40 + 이동 근사 시간 이후에 놓이고, 로봇 방과후가 추천 비교표에 유형 "방과후"로 나온다.

### FLOW-04 로그인·자녀 등록

**사용자·상황:** 맞벌이 보호자가 처음 서비스를 열어 시드 계정으로 로그인하고, 초5 자녀를 등록한다. 재로그인·다단계 승인 없이 한 번에 끝나야 한다(intent 6장 피할 패턴).

1. 로그인 화면에서 아이디·비밀번호를 넣고 '로그인'을 누른다. 보호자는 챗봇 홈, 학원 담당자는 학원 프로그램 관리, 학교 담당자는 학교 시간표 관리가 열린다.
2. 보호자가 하단 탭 '자녀'에서 '자녀 등록'을 누른다.
3. 별칭, 만 나이 11, 학년 초5, 학교, 관심사=과학, 교육 목표=수학 심화, 기존 일정(토 10:00~12:00 수영)을 넣는다. 만 나이가 14 미만이라 '법정대리인 동의 확인(모의)'을 체크한다.
4. **가치 전달 순간:** '자녀 저장'을 누르면 자녀 목록에 별칭과 학년이 보이고, 챗봇이 이 자녀의 조건을 기억해 다음 대화에서 쓴다. 새로 고쳐도 로그인 화면이 다시 나오지 않는다.

### FLOW-05 학원 프로그램 등록·관리

1. 사이드바 '프로그램'에서 목록을 본다. 월 교습비를 비워 둔 프로그램은 "미공개"로 보인다.
2. '프로그램 등록'에서 과목=코딩, 유형=교과 학원, 요일=화·목, 16:00~17:00, 월 교습비 200,000원, 월 기타경비 20,000원, 강사, 대상 학년=초4~초6, 정원 10, 현재 인원 3, 위도·경도를 넣는다.
3. '프로그램 저장'을 누르면 목록에 월 교습비와 월 기타경비가 나뉜 채 새 행이 보인다.
4. 확정 계획에 쓰이지 않은 프로그램은 '삭제' 확인 팝업으로 지운다.
5. **가치 전달 순간:** 담당자가 입력한 프로그램이 보호자 추천 비교표에 바로 후보로 나오고(미공개·마감은 빠짐), 삭제한 프로그램은 더 이상 나오지 않는다.

| 권한 없음 | 학원 B 프로그램 주소 접근·수정, 보호자의 프로그램 수정 API | "찾을 수 없어요"(404) 또는 "접근 권한을 확인하십시오"(403) | 요청 → 404·403 | 학원 B 값 그대로 | 내 학원 목록으로 |

## Inspiration & Anti-patterns (참고와 피할 것)

- **참고:** 주간 시간표 보기(하원나우, intent 6장 L3-06)와 학원별 지출 합계(위클링, L3-07)를 일정표와 월 학원비 요약에 쓴다. KDS AI 화면 구조(대화 → 추천 질문 → 입력창)와 Seamless Flow의 "결과 먼저, 다음 행동 붙이기"를 따른다.
- **참고:** 학원 정보는 명칭·교습과정·교습비·기타경비를 나눠 보인다(학원법 정보공개 항목, intent 12장).
- **피할 것:** 매번 재로그인, 자녀 연결용 별도 앱·다단계 승인(나이스 학부모서비스 리뷰 불만, L5-01·L5-04) — 로그인 유지와 한 화면 자녀 등록으로 피한다.
- **피할 것:** 보호자가 수업 시간·학원비를 하나씩 손으로 입력하는 일정 앱 방식(L3-05·L3-07) — 기관이 입력한 정보를 쓰고 보호자는 조건만 말한다.
- **피할 것:** 재원 인증 리뷰·커뮤니티(L3-02) — 이번 버전 제외 범위다.
- **피할 것:** LLM 문장 속 숫자를 일정·금액으로 쓰는 것 — 숫자는 모두 결정형 엔진 결과를 보인다.
